# Customer 360 Portfolio Demo

一个使用纯 Python 标准库实现的脱敏演示，展示如何把电商订单身份与私域身份连接为可追溯的客户资产。

> 这是作品集重构版，不是内部生产仓库。所有名称、订单号、SKU 和金额均为合成数据；仓库不包含客户信息、公司接口、密钥、部署地址或生产源码。

## 解决的问题

不同系统往往分别保存电商昵称、微信身份、群昵称和订单事实。直接按昵称模糊合并容易串人。本演示采用“订单号精确证据优先”的策略：

```text
电商交易订单 ──精确订单号── 私域 CRM 订单
       │                         │
       └──── 身份图与冲突隔离 ──┘
                    ↓
       消费、频次、最近购买、SKU 偏好
```

## 可验证机制

- 订单号始终按字符串处理，拒绝非法或含糊值。
- 只有唯一微信身份命中时才建立跨渠道关系。
- 同一订单出现多个微信身份时进入冲突队列，不自动猜测。
- 消费金额以分保存，画像由订单事实确定性计算。
- 输出保留 `linked`、`taobao_only`、`conflict` 三类身份状态。

## 运行

```bash
python3 demo.py sample_data.json
python3 -m unittest -v test_demo.py
```

## 与真实项目的边界

真实项目还包含 RPA、CRM、PostgreSQL、飞书同步、完整性审计和 AI 建议等模块。本仓库只公开可复用的领域模型与安全原则，不公开组织数据和基础设施细节。
